# Run and deploy the board

For whoever maintains the board. Teammates do not need any of this; the front page is `README.md`. `./hub setup` does the first deploy for you; this page is what it does, and how to do it by hand.

The board is a Next.js app in this repo. It reads the same event files the `./hub` CLI writes and folds them with the same `lib/hub/fold.mjs`. Data contract: `docs/CONTRACT.md`. Design notes: `docs/design.md`.

## Run locally

```bash
pnpm install
pnpm dev            # http://localhost:3000, reads and writes this checkout on disk
pnpm test           # web tests (vitest, tests/web)
pnpm test:hub       # CLI and fold tests (node --test, tests/hub)
pnpm test:all       # both
pnpm typecheck      # next typegen, then tsc
pnpm build
```

To point the dev server at another hub folder: `HUB_LOCAL_DIR=/path/to/hub pnpm dev`. Web writes then land in that folder's `events/`, and the board takes the event's name and dates from that folder's `hub.config.json`. The base path and time zone always come from the app folder's own `hub.config.json`, read at build time. A broken `hub.config.json` in the app folder stops `next build` and `next start`; a broken one in the data shows a warning on the home page, and the board falls back to the deployed settings. A populated sample hub ships with the tests: `HUB_LOCAL_DIR=tests/fixtures/demo-hub pnpm dev`.

`next-env.d.ts` is generated by `next dev`, `next build`, and `next typegen`, and is gitignored, as the Next.js docs recommend.

Screenshots of every view at 390 and 1440 px, light and dark: start the dev server, then `pnpm shots` (the address defaults to localhost:3000 plus `hub.basePath`; with `HUB_KEY` set in the environment the script opens the unlock link first; `HUB_SHOT_PAGES=home,knowledge` narrows it; needs `pnpm exec playwright install chromium` once; `shots/` is gitignored).

## Deploy on Vercel (standalone, the default)

The board gets its own Vercel project and its own address, for example `https://<project>.vercel.app`. `hub.basePath` in `hub.config.json` stays `""`.

1. `vercel link` in the hub folder (creates `.vercel/`, gitignored).
2. Set the environment variables below for Production (`vercel env add HUB_KEY production`, and so on). Each command prompts for the value, so it never lands in your shell history.
3. Deploy: `pnpm build && vercel deploy --prod` (or `./hub setup --deploy`, which also checks the board from outside).
4. Share `https://<your board>/unlock?key=<HUB_KEY>` with the team, privately. `./hub setup` prints this link only on a terminal; when its output is not a terminal, or with `--yes`, it writes the link to `.hub-owner.local` (gitignored, mode 0600) and says so, so the key stays out of agent transcripts and logs. `--print-link` prints it anyway.

### Why deploys are by hand, never from git

`vercel.json` sets `"git": { "deploymentEnabled": false }`. A hub makes hundreds or a thousand small commits a day (every `./hub` write is one), and Vercel's free plan allows 100 deployments a day; a skipped build still counts. So pushing deploys nothing, and the board is deployed with `vercel deploy --prod` (setup runs it once). Setup creates the Vercel project with the CLI and never connects it to the GitHub repo, so a push has nothing to start; `vercel.json` keeps it that way if someone connects the repo later. Keep `"framework": "nextjs"` in `vercel.json`: a project the CLI creates may not detect the framework on its own, and without it the deploy can fail.

Data does not need a deploy. With a token set (below), the board reads the repo directly and a data commit shows up within about 30 seconds. Redeploy only when the app code, `hub.config.json`'s `basePath` or `timezone`, or an environment variable changes.

**One rule keeps two deployers from undoing each other: only deploy a clean tree that equals `origin/main`.** Merge your branch to `main` first (rebase on `origin/main`, push with a fast-forward, never force), then deploy from a checkout at that commit. `pnpm build` runs first because it also typechecks the tests.

## Environment

Copy `.env.example` to `.env.local` for local overrides. Never commit real values.

| Variable | Where | What |
|---|---|---|
| `HUB_KEY` | production | secret for the unlock link; unset in production means every page is a 404 |
| `HUB_READ_TOKEN` | production | the token the board reads the repo with. `./hub setup --tokens` sets it to the same read and write token as `HUB_WRITE_TOKEN`; `--separate-tokens` sets a **Contents: read-only** token instead. When you replace the token by hand, update both |
| `HUB_WRITE_TOKEN` | production | fine-grained token, this repo only, **Contents: read and write**; the board saves events with it (and reads with it when `HUB_READ_TOKEN` is unset) |
| `HUB_REPO` | optional | `owner/name` of this private repo. Without it the board uses `hub.repo` from `hub.config.json`, then the repo Vercel built from |
| `HUB_LOCAL_DIR` | optional | read and write a checkout on disk instead of GitHub |

Reads come from disk in development, when `HUB_LOCAL_DIR` is set, or when no token or repo is known (in production that means the files bundled into the last deploy). Otherwise the app fetches `GET /repos/{owner}/{repo}/tarball/main` once per 30 second window, unpacks it in memory, and keeps only `events/**.json`, `kb/**.md`, `team.json`, `hub.config.json`, and `docs/agent-prompt.md`. A failed read serves the last snapshot this instance saw instead of a blank board.

Writes go to disk only in development or with `HUB_LOCAL_DIR`; a deployed board never writes to its own files. Without a repo and `HUB_WRITE_TOKEN`, every write control on the board says so before anyone presses it (`writesOffReason` in `lib/web/source.ts`). Writes (`POST /api/event`) check same origin (behind a parent site the public host arrives as `x-forwarded-host`), rate limit per address, validate with zod and `validateEvent`, set `via: "web"`, and create one new file `events/YYYY-MM-DD/<id>.json` through the GitHub contents API, retrying on 409 and 5xx.

## Tokens

The default is one token: a fine-grained personal access token (GitHub, Settings, Developer settings, Fine-grained tokens) with **Repository access: Only select repositories** set to this one repo and **Contents: Read and write**. `./hub setup --tokens` prints a link to the token page with those settings filled in, asks for the token, and saves it as both `HUB_READ_TOKEN` and `HUB_WRITE_TOKEN`.

For least privilege, `./hub setup --separate-tokens` asks for two: the read and write one as `HUB_WRITE_TOKEN`, and a second with **Contents: Read-only** as `HUB_READ_TOKEN`. Nothing else either way, and never a classic token. Give tokens an expiry a few days after the event. To rotate by hand, set the new token on every variable that held the old one (`vercel env rm`, then `vercel env add`), then `./hub setup --deploy`.

## Access

Every path, the API and static assets included, sits behind a signed cookie. Share `<board address>/unlock?key=<HUB_KEY>` with the team once; it sets a cookie that carries a signed expiry 14 days out, checked on the server, so an old cookie stops working even if a browser keeps it (`Path` is the base path, or `/`; HttpOnly, SameSite=Lax, Secure in production) and redirects home with a path-only `Location`. Anyone without it gets a bare 404. Rotate `HUB_KEY` to sign everyone out. In development with `HUB_KEY` unset the board is open. The key travels in a URL, so it can land in browser history: treat the link like a shared password for one weekend.

Vercel's default Deployment Protection sends anyone without a Vercel login on your team to a Vercel sign-in page from each deployment's own address (`https://<project>-<hash>-<team>.vercel.app`). It leaves the production address (`https://<project>.vercel.app`, or your own domain) open, and that is the one setup prints and checks. Share only that address; leave the protection on.

## Optional: mount the board under a path on another site

If you want the board at `https://your-site.example/hub` instead of its own address:

1. Set `hub.basePath` to `"/hub"` in `hub.config.json` and redeploy. Every URL of the app then starts with `/hub` (`next.config.ts` sets Next's `basePath` from it); `/` and `/board` without the prefix are a 404, locally too.
2. In the parent site, rewrite `/hub` and `/hub/:path+` to this project's origin at the same path.

What changes when you write code for a mounted board:

- `<Link>`, the router, `/_next` assets, and the icon get the base path from Next. Next does not prefix `fetch`, plain `<a>` and `<img>`, or the HTML that `lib/web/markdown.ts` renders: use `withBasePath()` from `lib/web/base-path.ts` for those (it is a no-op on a standalone board).
- Behind the rewrite, the host this app sees is its own `vercel.app` origin, not the public one. Never build a redirect from `request.url`; send a path-only `Location` (see `app/unlock/route.ts`). A proxy redirect must be absolute, which is why the unlock link is a route handler and `proxy.ts` never redirects.
- The `proxy.ts` matcher is relative to the base path and needs its own `"/"` entry to cover the base path root.
- The parent's rewrite adds Next's `.rsc` suffix to the home page, which made the home page reload in full; `proxy.ts` rewrites the root to itself to fix it, only when a base path is set.

Every response carries `X-Robots-Tag: noindex, nofollow` (`next.config.ts`), and every page has noindex, nofollow robots metadata (`app/layout.tsx`).

## Code layout

```
app/                 routes: / (home: map, time left, needs you, who is on what), /board (items and the feed), /calendar (Schedule), /kb, /kb/[...slug], /decide and /design (linked, not tabs), /p/[id], /script (lines from kb/pitch-script.md), /api/event, /api/clock, /unlock
components/          UI; client components are marked "use client"
lib/web/             base-path, source (disk or tarball), hub (fold + kb + schedule + config), event-config, write, auth, graph (the map), playbook, markdown
lib/hub/             schema, fold, and config, shared with the tool
proxy.ts             the cookie gate (the unlock link itself is app/unlock/route.ts)
tests/web/           vitest tests and the screenshot script
tests/fixtures/      the demo hub
```
